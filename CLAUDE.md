# CLAUDE.md — kontekst projektu

## Cel
Statyczny, szybki serwis afiliacyjny **„Okazje i Prezenty”** (okazje + kody rabatowe + pomysły na prezent) dla polskiego wydawcy sieci **webePartners**. Ruch głównie z Facebooka na telefonach → mobile-first. Odwiedzający klika w produkt/kod → trafia do sklepu przez link afiliacyjny. Użytkownik (Grzegorz) to osoba techniczna planująca sprzedaż na Allegro; zależy mu na niskich kosztach — **żadnych płatnych usług ani zależności wymagających konta**. Język treści i komunikatów: polski.

## Etapy
1. **ETAP 1 (zrobiony)** — projekt Astro + Tailwind, skrypt pobierania danych, fixtures, strony, SEO, README.
2. **ETAP 2 (zrobiony)** — wdrożenie: `.github/workflows/deploy.yml` (cron 04:15 UTC, ręcznie, push na `main`) → test → build → FTPS (SamKirkland/FTP-Deploy-Action) do `public_html` subdomeny na DirectAdmin. Sekrety repo: `WEBE_LOGIN`, `WEBE_PASSWORD`, `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`. `SITE_URL` jest w workflow (jawnie, nie sekret).
3. **ETAP 3 (zrobiony)** — uczciwe ceny (polityka Omnibus, patrz niżej), kolekcje prezentowe wg budżetu (`/prezenty/do-50-zl`, `50-200-zl`, `powyzej-200-zl`, rozłączne; konfiguracja `COLLECTIONS` w `site.mjs`; kolekcja z <3 produktami jest ukrywana), przegląd nowo zaakceptowanych sklepów (Crong.com odrzucony tematycznie → `pominiete` w `programs.json`). Dalej: kolejne sklepy po akceptacji, poradniki/treści SEO.

## Architektura
- `scripts/fetch-data.mjs` — pobiera `GetPrograms`, `GetHotPrice` (per program z konfiguracji), `GetVouchers`; normalizuje (`scripts/normalize.mjs`) i zapisuje do `src/data/*.json` (`products`, `vouchers`, `shops`, `meta`). `src/data/` jest w `.gitignore` (generowane).
  - Tryby: `WEBE_LOGIN`+`WEBE_PASSWORD` → Basic Auth (Actions); `WEBE_PROXY_AUTH=1` → bez nagłówka (sesje Claude w chmurze; proxy dokłada auth; skrypt sam ustawia `NODE_USE_ENV_PROXY=1`); brak env → `fixtures/`.
  - `REQUIRE_LIVE=1` (ustawiane w CI) → brak danych logowania = błąd zamiast cichego użycia fixtures.
  - W trybie live pusty wynik = błąd (exit 1), żeby nie opublikować pustej strony.
  - `GetHotPrice` bez `programId` zwraca tylko ~2000 pozycji (dominują sklepy spoza konfiguracji) — dlatego zawsze pobieramy osobno dla każdego programu z konfiguracji.
- `src/config/programs.json` — **lista sklepów** (`programs`, ręczna), `automatyczne` (autodetekcja), kandydaci czekający na akceptację (`oczekujace`, nieużywani), `pominiete` (zaakceptowane, ale odrzucone tematycznie), wykluczenia (`wykluczoneKategorie`, `wykluczoneFrazy`, `wykluczoneNazwy`, `wykluczoneSlowaWNazwie`), limity (`maxProduktowNaSklep`=150, `idealnaCenaPrezentu`). Env `PROGRAM_IDS=1,2,3` nadpisuje listę (testy; bez kontroli statusu i bez auto).
- **Automatyczna aktualizacja oferty** (`scripts/programs.mjs` → `pickPrograms`, codziennie przy buildzie): (1) sklep ręczny jest pokazywany tylko gdy w `GetPrograms` ma `relationId=4`; zakończony/odrzucony znika sam, a po powrocie do statusu 4 wraca; (2) `automatyczne.wlaczone=true` → nowo zaakceptowane programy z feedem (`isXml`) i kategorią z `kategorieDozwolone` (bez `kategorieWykluczone`, `wykluczoneProgramy`, `pominiete`) są dodawane same (`auto:true`, w logu „NOWY SKLEP”); (3) produkty znikają/wracają razem z feedem (`GetHotPrice` per program); (4) błąd sieci/5xx przy `GetHotPrice` **przerywa build** (na serwerze zostaje wczorajsza wersja — nie publikujemy niepełnej oferty), 4xx = program bez feedu (pomijany); (4b) **martwy feed**: program, którego najnowszy wpis w historii cen (`previousPrice`) jest starszy niż `maxWiekFeeduDni` (150, `programs.json`), jest pomijany (log „nieaktualny feed”) — sklep przestał aktualizować ofertę, a webePartners przekierowuje wtedy na `webep1.com/shopnotactive` („sklep niedostępny”; tak było z 262.pl, feed z 2025-12); (5) duże feedy przycinane do `maxProduktowNaSklep` (`capProducts`: wszystkie obniżki + rotacja po typach produktu `productType`, ceny zbliżone do typowej ceny prezentu); (6) podsumowanie oferty w Actions → Summary oraz w `meta.json` (`perShop`, `added`, `skipped`) i w feedzie `/api/okazje.json` (`shops`).
- **LeadStar.pl (druga sieć, tylko kody)** — `scripts/leadstar.mjs`, konfiguracja `programs.json` → `leadstar` (`wlaczone`, `produktyDozwolone`, `wykluczoneProgramy`). API: POST `https://leadstar.pl/api/{programs,coupons}` z `partner_id` + `api_key` (sekrety repo `LEADSTAR_PARTNER_ID`, `LEADSTAR_API_KEY`; bez nich LeadStar jest pomijany, build się nie wywala; błąd API też tylko loguje — `meta.leadstar`). LeadStar **nie ma produktów z cenami** (feed XML `leadstar.pl/xml?...` to lista wszystkich ~315 programów: banki, pożyczki, sklepy — bez cen), więc bierzemy: zaakceptowane programy (`status=1`) z dozwolonych kategorii (`product`: uroda, biżuteria, dom i ogród, hobby, rtv i agd, sport i zdrowie, suplement, zakupy, zwierzęta, żywność — bez pożyczek/banków/mody/erotyki/dziecka) i ich aktualne kody. Sklep LeadStar pokazujemy tylko gdy ma ≥1 kod. ID programu = `1_000_000 + id` (brak kolizji z webePartners), ID kodu `ls-<coupon_id>`, `shops[].network='leadstar'`. Linki LeadStar nie dostają `param1/param2` (to znaczniki webePartners; `trackedUrl()` i `/idz/` dokładają je tylko dla `webep1.com`). Logo z `img.leadmax.pl` (polityka prywatności to opisuje). Test lokalny bez kluczy: mock serwera + `LEADSTAR_API=http://127.0.0.1:PORT`.
- `src/config/site.mjs` — nazwa serwisu, tekst informacji o linkach partnerskich, kategorie serwisu (dopasowanie po słowach kluczowych z API), `MAX_TRUSTED_CUT`.
- `src/lib/data.mjs` — import danych, `trackedUrl()` (dokleja `param1=www&param2=<typ strony>`), formatowanie cen/dat.
- Strony: `/`, `/okazje` (filtry/sortowanie po stronie klienta, ~40 linii JS inline, stan w URL: `?sklep=&kategoria=&sort=`), `/kody-rabatowe`, `/sklep/[program]`, `/o-serwisie`, `/polityka-prywatnosci`, `/404`, `robots.txt`, `sitemap.xml`.
- `/api/okazje.json` — publiczny feed (produkty wg rabatu + kody, linki bez param1/param2) dla n8n: workflow „Okazje 02 — Posty z okazjami” (id `TMWxcTQdb9GrYGq9`) dokleja `param1=fb` i codziennie o 19:30 publikuje na fanpage **jeden post wielozdjęciowy z 3 rotującymi produktami** (węzeł AI Agent HUB, operacja `carousel`; na FB to wiele zdjęć w jednym poście, linki w opisie). Tryb „okazje” (świeże obniżki, tekst „Najniższa cena z 30 dni przed obniżką”, #reklama) lub „pomysły” (gdy brak ≥2 nowych okazji — bez twierdzeń o obniżce); historia w tabeli `okazje_posty_fb` (3 wiersze na post, blokada powtórzeń 30/14 dni). Harmonogram używa tylko wersji **opublikowanej** w n8n — po każdej zmianie `publish_workflow`. Nie zmieniaj nazw pól bez aktualizacji tego workflow.
- Karta produktu (`ProductCard.astro`): galeria zdjęć (`product.images`, max 8; scroll-snap + strzałki + licznik) i lightbox (`<dialog>` w `Base.astro`); kliknięcie zdjęcia powiększa, do sklepu prowadzi nazwa i przycisk. Suwak pozycji strony po prawej (`#scrollrail` w `Base.astro`, natywny pasek ukryty w `global.css`). Wszystkie strony używają jednego kontenera `.container-wide` (pełna szerokość, bez max-width; strony tekstowe dodatkowo `max-w-3xl`). Strona główna: `ProductRow` (telefon: kolumna, desktop: jeden rząd); baner (hero) ma w tle zdjęcia 3 produktów z `heroProducts` (`pickHeroProducts()` w `data.mjs`: najlepsze obniżki z różnych sklepów i „rodzin” nazw, uzupełnione biżuterią/perfumami) — telefon: pas 2 zdjęć u góry (trzecie `hidden sm:block`), desktop: całe tło pod półprzezroczystym panelem z tekstem.
- **Strony produktów** `/produkt/<slug>-<id8>` (`src/pages/produkt/[slug].astro`; `productPath()`/`relatedProducts()` w `data.mjs`): galeria, cena z informacją Omnibus, opis (do 600 znaków), przycisk „Zobacz w sklepie” (→ `/idz/<id>?z=produkt`; z `?z=fb` → `z=fb`, czyli param1=fb&param2=post), produkty powiązane, JSON-LD Product + BreadcrumbList, OG (`og:type=product`, zdjęcie produktu), w sitemap. Tytuł karty produktu linkuje do tej strony (zostaje w serwisie), przycisk karty do sklepu. Feed `/api/okazje.json` ma `pageUrl` — posty FB (n8n) linkują do strony produktu (`pageUrl?z=fb`) z fallbackiem na link afiliacyjny. Uwaga: strona produktu znika, gdy produkt wypadnie z feedu (stary link w poście → 404).
- **Przejście do sklepu:** karty produktów/kodów linkują do `/idz/<id>?z=<typ strony>` (`src/pages/idz/[id].astro`, noindex, `Disallow` w robots) — szybka, własna strona z logo sklepu i produktem, która od razu robi `location.replace` na link afiliacyjny z `param1=www&param2=<z>` (z whitelistą: glowna/okazje/kody/sklep/prezenty/produkt, `fb` → param1=fb&param2=post, inaczej `inne`). Adres docelowy jest wbudowany w build (nie z parametru URL — brak open redirect). Feed `/api/okazje.json` nadal ma surowe linki afiliacyjne.
- Kolekcje prezentowe: `/prezenty/do-50-zl`, `50-200-zl`, `powyzej-200-zl` (tylko z ≥3 produktami; w sitemap). `/okazje` ma filtr „tylko z aktualną obniżką” (`?obnizka=1`).
- **Kalkulator obligacji (LeadStar)** — `/kalkulator-obligacji` (`src/pages/kalkulator-obligacji.astro`): oficjalny kod osadzania LeadStar (`obligacje.leadstar.com.pl/getBondCode?pbc_id=41&pbc_hash=…` — parametry publiczne, nie sekret) ładowany **dopiero po kliknięciu „Pokaż kalkulator”** (zero zewnętrznych skryptów przy wejściu na stronę; potem LeadStar może ustawić własne cookies), z adnotacją reklamową i o ryzyku, linkiem zapasowym „otwórz w nowej karcie” i opisem w polityce prywatności. Menu: pozycja „Obligacje” tylko od szerokości `sm` (na telefonie 360 px nagłówek by się przepełnił), zawsze w stopce; w sitemap. Pola `pbc_epi1/pbc_epi2` puste (znaczniki źródła — nieznane znaczenie). Pożyczki/banki/ubezpieczenia świadomie NIE są promowane (reklama regulowana).
- Brak bazy, backendu, analityki i cookies (poza stroną kalkulatora po kliknięciu — patrz wyżej).

## Fakty o API (sprawdzone na prawdziwych danych, 2026-10-21)
- `productImages` to **obiekt** `{productImagesUrl: [], productThumbUrl}`; `category.webeCategoryName` to tablica; opis w polu `productDescritption` (sic!). Czasem brak kategorii (Paryskie) → kategoria z `shopCategoryName`/nazwy.
- `priceCut` z API **ignorujemy** (liczony od najwyższej ceny w historii, nawet sprzed 2 lat — np. 262.pl ma „obniżki” sprzed 602 dni). **Polityka cen (Omnibus):** `computeDeal()` w `scripts/normalize.mjs` liczy obniżkę z `previousPrice`: początek obecnej ceny = ostatni wpis równy cenie dziś; cena odniesienia = najniższa cena z 30 dni przed tą datą; znaczek -X% i przekreślona cena tylko gdy obecna cena obowiązuje ≤ `DEAL_MAX_AGE_DAYS` (30) dni, odniesienie > cena i obniżka ≤ `MAX_TRUSTED_CUT` (70%). Inaczej `oldPrice=null, discount=0` (produkt widoczny, bez znaczka). Pole `dealSince` = data początku obniżki. Efekt (2026-10-22): 27 z 72 produktów ma obniżkę (wszystkie gadzetyrajdowe.pl + 1 Paryskie); feed dla n8n zawiera `oldPrice/discount` tylko przy takich obniżkach.
- `relationId`: 4 = zaakceptowany (13 programów), 1 = prawdopodobnie oczekuje na akceptację, 0 = brak relacji. Produkty zwracają tylko zaakceptowane programy.
- Linki afiliacyjne mają już `?r=...` — parametry dokładamy przez `URL.searchParams`.
- `voucherCode` bywa opisem („zapis do newslettera”), nie kodem — wtedy `code=null` i karta ma tylko „Przejdź do promocji”.

## Zasady
- **Prawo konsumenckie / uczciwość:** (1) polityka cen Omnibus (patrz Fakty o API); (2) `programs.json` → `wykluczoneFrazy` (zamiennik/nalewane/inspirowane/odpowiednik w nazwie lub opisie) i `wykluczoneNazwy` (regex, np. numerowana linia „N° 126” Paryskie.pl) — odrzucamy zamienniki perfum i produkty o niejasnym opisie; (3) termin ważności kodu zawsze jako realna data z API; (4) oznaczenie reklamy/linków partnerskich w stopce, nad listami i w postach FB (#reklama); (5) **`OPERATOR` w `src/config/site.mjs` (dane wydawcy: nazwa, adres, NIP, e-mail) MUSI być uzupełniony przed publicznym startem** — do tego czasu strony „O serwisie” i „Polityka prywatności” pokazują komunikat, a build ostrzega `[OperatorInfo]`; (6) polityka prywatności opisuje zasoby zewnętrzne (obrazy z `image.weben1.com`).
- Sekrety wyłącznie z env — nigdy w kodzie/commitach. Zmienna `SITE_URL` ustala domenę (canonical, OG, sitemap); zmiana domeny = jedna zmienna w `deploy.yml`.
- Linki afiliacyjne (i linki do `/idz/`): `rel="sponsored nofollow noopener" target="_blank"`. Informacja o linkach partnerskich widoczna w stopce i nad listami; ceny z dopiskiem „cena z dnia <data aktualizacji>”.
- Nie pokazujemy: erotyka, dla dziecka/zabawki/parenting, odzież i obuwie (słowa w `wykluczoneSlowaWNazwie`).
- Oszczędzaj kontekst: dużych odpowiedzi API nie czytaj w całości (`jq`/`head`).
- Użytkownik prosi o dokończenie zadania do końca i potwierdzenie; zwracaj się do niego „Grzegorz”.

- **Torebki-skórzane.pl (12354) wyłączony ręcznie** (`wykluczoneProgramy`, 2026-10-22): `relationId=4`, świeży feed, ale link śledzący kończy na `webep1.com/shopnotactive` („sklep niedostępny”) — status widać tylko po kliknięciu, API go nie zdradza. Przywrócić (usunąć z `wykluczoneProgramy`) po potwierdzeniu w panelu webePartners, że program jest aktywny.
